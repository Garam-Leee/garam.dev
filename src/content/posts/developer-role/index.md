# AI 시대에도 사라지지 않을 개발자의 역할

AI가 코드를 대신 작성하는 시대가 오고 있다. 그럼에도 개발자가 여전히 필요한 이유에 대해 생각해봤다.

요즘 개발 관련 이야기를 듣다 보면 비슷한 말을 자주 접하게 된다.

> 개발자는 필요 없어질 것이다.
>
> 이제 코드는 AI가 다 작성한다.
>
> 실행 비용이 거의 0이 되는 시대다.

몇 년 전만 해도 조금 과장된 이야기처럼 들렸는데, 최근에는 마냥 틀린 말이라고 하기 어려워졌다. 실제로 나 역시 AI를 활용하는 시간이 크게 늘었다. 예전에는 직접 작성했을 코드를 이제는 AI에게 맡기는 경우가 많다.

그렇다면 정말 개발자의 역할은 사라지는 걸까?

## AI는 개발자의 가능성을 확장한다

Josh W. Comeau는 [*The End of Front-End Development*](https://www.joshwcomeau.com/blog/the-end-of-frontend-development/)에서 AI를 기존 전문직의 생산성을 높여주는 도구에 비유한다.

전동 공구가 등장했다고 목수가 사라지지 않았고, 스프레드시트가 등장했다고 회계사가 사라지지 않았다. 개발도 마찬가지라고 생각한다.

실제로 AI를 활용하면서 많은 변화가 생겼다.

- 반복적인 코드 작성에 쓰는 시간이 줄었다.
- 새로운 기술을 배우는 속도가 빨라졌다.
- 아이디어를 빠르게 시제품으로 만들고 검증할 수 있게 됐다.
- 익숙하지 않은 개발 영역에도 도전할 수 있게 됐다.

이해하기 어려운 기술을 마주했을 때 언제든 질문하고 답변을 얻을 수 있다는 점도 좋았다. AI 덕분에 개발자가 할 수 있는 일의 범위가 넓어졌다.

그런데 우리는 정말 더 빠르게 개발하고 있을까?

## 체감하는 생산성과 실제 생산성

2025년 [METR의 연구](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/)에서는 숙련된 오픈소스 개발자 16명이 익숙한 프로젝트의 작업을 수행할 때 AI 도구가 생산성에 미치는 영향을 살펴봤다.

| 구분 | 결과 |
| :--- | ---: |
| 실험 전 개발자들이 예상한 작업 시간 단축 | 24% |
| 실험 후 개발자들이 체감한 작업 시간 단축 | 20% |
| 실제 측정된 작업 완료 시간 | 19% 증가 |

개발자들은 더 빠르게 일했다고 느꼈지만, 이 실험에서는 AI를 사용한 작업에 오히려 더 많은 시간이 걸렸다. 2025년 초의 도구와 특정 개발 환경을 대상으로 한 결과이므로, 모든 개발 상황에 그대로 적용할 수는 없다.

다만 나 역시 비슷한 경험이 있다. AI에게 원하는 결과를 얻기 위해 여러 번 요청하고 코드를 수정하다 보면, 차라리 처음부터 직접 작성하는 편이 더 빠르겠다는 생각이 들 때가 있다.

**코드 생성 속도와 개발 생산성은 다르다.** 코드를 작성하는 시간뿐 아니라 검토하고 수정하는 시간도 개발 과정의 일부이기 때문이다.

## 그런데 문제는 원래 코드가 아니었다

코드를 작성하는 시간이 줄어들어도 개발 과정에서 고민해야 할 문제는 여전히 많다.

- 사용자는 정말 이 기능이 필요한가?
- 어떤 방식이 가장 자연스러운 경험일까?
- 현재 프로젝트에 적절한 설계일까?
- 장기적으로 유지보수할 수 있는 구조일까?
- 지금 해결하려는 문제가 맞는가?

AI는 구현을 도와준다. 하지만 무엇을 만들어야 하는지, 왜 만들어야 하는지에 대한 판단은 여전히 필요하다. 요청받은 기능을 구현하는 것과 실제 문제를 해결하는 것은 다르기 때문이다.

구현에 드는 비용이 줄어들수록 오히려 문제를 제대로 정의하는 일이 중요해지지 않을까.

## AI를 활용하더라도 핸들은 놓지 말아야 한다

Josh W. Comeau는 후속 글인 [*The Post-Developer Era*](https://www.joshwcomeau.com/blog/the-post-developer-era/)에서 AI를 활용한 개발을 크루즈 컨트롤을 켜고 운전하는 것에 비유한다. 운전이 편해지더라도 방향을 확인하고 조정하는 일은 여전히 운전자의 몫이다.

실무에 AI를 처음 도입했을 때 나 역시 많은 시행착오를 겪었다. 기존 프로젝트의 구조를 고려하지 않거나 코딩 컨벤션을 따르지 않는 코드를 생성하는 경우가 많았다.

이를 개선하기 위해 프로젝트의 규칙을 정리하고, AI에게 충분한 맥락을 제공하기 시작했다. 자연스럽게 내가 수행하는 역할에도 변화가 생겼다.

- 프로젝트의 규칙과 작업 기준 정립
- 요구사항과 작업 범위 정의
- AI가 생성한 코드 검토
- 작업 내역과 변경 사항 관리

코드를 직접 작성하는 것 외에도 신경 써야 할 일이 많아졌다. AI를 잘 활용하려면 AI가 무엇을 잘하고 무엇을 놓치고 있는지 판단할 수 있어야 한다. 결국 개발자의 기술적 이해와 전문성이 여전히 중요한 이유이기도 하다.

## 앞으로 더 중요해질 것들

AI가 발전할수록 오히려 중요해질 역량들이 있다고 생각한다.

### 문제 정의와 해결

무엇을 해결해야 하는지 이해하고, 여러 해결책 중 적절한 방법을 선택하는 능력.

### 설계와 아키텍처

단순히 작동하는 코드를 넘어 프로젝트의 구조와 확장성, 유지보수까지 고려하는 능력.

### 도메인 지식

사용자와 비즈니스를 이해하고, 기술을 통해 필요한 가치를 만들어 내는 능력.

### 품질 관리

AI가 생성한 결과물의 정확성과 품질을 판단하고 검증하는 능력.

### 커뮤니케이션

문제를 명확하게 설명하고, 요구사항을 조율하며, 서로의 맥락을 공유하는 능력.

생각해보면 원래도 중요했던 것들이다. 다만 그동안은 구현이라는 큰 업무에 가려져 있었을 뿐이다.

## 마무리

AI 덕분에 개발 방식은 많이 바뀌고 있고, 앞으로도 더 바뀔 것이다. 하지만 개발자의 기존 역량이 필요 없어지는 것은 아니라고 생각한다.

문제를 정의하고, 해결책을 설계하고, 결과물의 품질을 판단하는 일은 여전히 중요하다. 여기에 AI에게 맥락을 전달하고, 작업을 위임하고, 결과를 관리하는 역할이 더해지고 있다.

**개발자의 역할은 사라지는 것이 아니라 확장되고 있다.**

결국 AI를 얼마나 잘 다루는가보다 AI와 함께 어떤 문제를 해결할 수 있는가가 더 중요하지 않을까.
